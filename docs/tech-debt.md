# Technical debt

Maintained by `tech-lead-po`. Implementers report debt in their task's Implementation log; do not edit this file directly.

| ID | Debt | Impact | Origin | Proposed fix |
|---|---|---|---|---|
| D-001 | Quiz questions are read from PostgreSQL on every question start / answer instead of being snapshotted in Redis at game start. | Extra DB load per answer; editing a quiz during a live game breaks the game (question/option ids re-created). | T-008 framing | Snapshot questions (without exposing `isCorrect`) in Redis at game creation. |
| D-002 | `GameSession.pin` is `@unique`: a PIN is never reusable historically, numeric PIN space (900k) is consumed forever. | PIN generation slows down / falls back to 8 digits as history grows. | ADR 0001 | Drop `@unique` on `pin`, keep an index, look up sessions by id. Requires a schema change (user decision). |
| D-003 | WebSocket rooms and timers live in process memory. | Single backend instance only; a restart loses running timers. | ADR 0001 | Redis pub/sub + timer recovery when multi-instance is needed. |
| D-004 | `hostToken` stored in `localStorage`. | Same XSS exposure as the existing `auth_token`. | ADR 0001 | Revisit with a global XSS/CSP hardening task. |
| D-005 | Unused dependencies after ADR 0001: `@nestjs/platform-socket.io`, `socket.io` (and possibly `@nestjs/platform-fastify`, `fastify`); root `package.json` + `node_modules` with `@nestjs/*` ^12 (likely accidental install). `@nestjs/websockets` used but not declared. | Install size, confusion, version drift. | Review | User decision (dependency change / deletion = sensitive action). |
| D-006 | Join page has 6 input boxes while PINs can be 8 chars (rare fallback). | An 8-char PIN can only be joined through `?code=` link. | T-009 framing | Revisit if the fallback is ever observed in logs. |
| D-007 | Backend devDependencies added by T-002/T-006 without recorded approval, unused or inconsistent: `@testcontainers/postgresql`, `@testcontainers/redis` (unneeded since the no-Docker decision of 2026-11-20), `jest-environment-node` ^30 alongside `jest` ^29, `@types/joi` (deprecated stubs, `joi` 18 ships its own types). `ioredis-mock` is unused today but KEPT: T-011/T-012/T-014 use it. | Version drift, possible Jest environment mismatch, install size. | Retro review T-002, T-006 | User decision pending: remove `@testcontainers/postgresql`, `@testcontainers/redis`, `jest-environment-node`, `@types/joi` (dependency change = sensitive action). Keep `ioredis-mock`. |
| D-008 | Global `ValidationPipe` uses `enableImplicitConversion: true` (`main.ts`). | A string `"false"` becomes `true` for `@IsBoolean` fields (`isCorrect`); harmless for JSON clients, surprising otherwise. | Retro review T-004 | Disable implicit conversion and use explicit `@Type(() => Number)` on query params; needs a check of every `@Query`. |
| D-009 | `RoomParticipant.score` / `correctAnswersCount` are never updated and duplicate `PlayerResult`. | Misleading data model; anyone reading the table gets zeros. | Retro review T-007 | Drop the two columns (schema change, user decision) or document them as unused. |
| D-011 | ADR 0001 v1 `QUESTION_RESULT` snapshot has `question:ended` but no `question:started`: after a reload on the result screen the client has no question text / option texts. | Host screen shows leaderboard without distribution labels; player sees correct/incorrect + points but not the correct answer text. Rare (reload during a 10-20 s window). | Review T-009 (I-2) | ADR 0001 v2: additive `questionText` + `options` on `question:ended`, then client fallback. Not during T-008. |
| D-012 | `host:create_game` / `player:join` re-sent by the auto-reconnect when the socket drops before the reply. | Orphan anonymous game (self-cleans via `LOBBY_EXPIRED` ~64 s) / ghost disconnected player + `NICKNAME_TAKEN` on the player's own nickname. Rare (drop within one RTT). | Review T-009 | ADR 0001 v2: idempotent create/join with a client-generated request id. |
| D-013 | A player who closes the tab on the podium keeps `player_token` / `player_pin`; next `/player/join` visit does one failed `player:reconnect` before showing the form. | One extra round trip and an "invalid session" notice. | Review T-009 | Clear the stored session on `game:podium` + timeout, or accept. |
| D-014 | No WebSocket rate limiting: the global throttler is skipped on the gateway (it cannot key WS messages); only `maxPayload` 16 KB. Anonymous `host:create_game` is unlimited (one `GameSession` row + Redis state per call). | Message flooding, DB/Redis growth by anonymous game creation. | Review T-008 | T-020 (P1): per-socket message limit + per-IP `host:create_game` limit. Before any exposure beyond localhost. |
| D-015 | Lobby expiry with 0 players: `Room` stays `LOBBY` and `GameSession` stays `LOBBY`; during the 5 s grace the Redis state is still `LOBBY` (join accepted, host re-join restarts a 59 s countdown) before deletion. | Stale DB rows; rare confusing join that dies 5 s later. | Review T-008 (I-2) | T-018: terminal state on expiry + `ABANDONED`. |
| D-016 | Games abandoned mid-way (host never clicks next, REST game never hosted) are never finalized: `GameSession` `LOBBY`/`QUESTION_ACTIVE` and `Room` `LOBBY`/`IN_PROGRESS` forever; Redis keys expire after 24 h only. A REST game never joined by its host has no lobby timer: players can wait forever. | Misleading history, no results saved. | Review T-008 | Idle-game sweeper (status + last activity), or lobby timer started at creation. Decide with product. |
| D-017 | Legacy `POST /api/games/:code/start` (`GameService.startGame`) throws plain `Error` → HTTP 500; unused by the WS flow. | Wrong status codes, dead endpoint. | T-008 log | T-018 (remove or map). |
| D-018 | Public unauthenticated endpoints return raw live data: `GET /api/games/:code` (incl. `hostId`, `quizId`, `roomId`), `GET /api/games/:code/players`, `GET /api/players/game/:pin` (nicknames, scores, connected), `GET /api/players/session/:id` (all results). | Low-severity disclosure; nickname harvesting by PIN enumeration (6-digit space). | T-008 log + review | T-018 (projection or removal, extended to `players` endpoints). |
| D-019 | The global `ValidationPipe` (with `enableImplicitConversion`) also runs on WS messages before the gateway pipe. Neutralized by the `@Transform(rawValue)` decorators. | Double validation; fragile if a WS DTO forgets `rawValue`. | T-008 log | Solve with D-008 (drop implicit conversion). |
| D-020 | `test/auth.e2e-spec.ts` / `test/quiz.e2e-spec.ts` likely stale (paths / fields) and `deleteMany()` against the configured DB. | False failures; data loss if run against the dev DB. | T-008 log | T-011. |
| D-021 | Player nicknames are persisted without retention limit in `PlayerResult` and `RoomParticipant`. | GDPR: pseudonymous personal data kept indefinitely, no deletion path. | Review T-008 | Retention policy (e.g. purge after N days) + document in `docs/context.md`. User decision. |
| D-022 | Lua scripts are sent as full text on every `EVAL` (no `defineCommand`/`EVALSHA`); multi-key scripts use keys without hash tags. | Minor bandwidth; incompatible with Redis Cluster. | Review T-008 | Revisit with D-003 (multi-instance): `defineCommand` + `game:{pin}:*` hash tags. |
| D-023 | Partial-failure handling in the engine: if `getQuestion` / `applyQuestionResults` fails after the CAS to `QUESTION_RESULT`, no `question:ended` is broadcast and points may be lost; `MULTI.exec()` per-command errors are not checked (`createGameState`, `applyQuestionResults`). | Host UI waits until refresh; silent score loss on Redis errors (rare). | Review T-008 (I-3) | Check exec results; retry or broadcast a fallback `question:ended`. |
| D-024 | The "dev" PostgreSQL used by the backend is a hosted database (alwaysdata), not a local one, contrary to the "local only" rule of `CLAUDE.md`. `prisma db push` was applied to it. | Any destructive command (`migrate dev` reset, `test:e2e` `deleteMany()`) hits a remote database; data in a third-party host (GDPR). | T-008 execution | User decision: confirm it is a disposable dev DB, or switch to a local DB; record in `docs/context.md`. |
| D-025 | Redis command volume on Upstash (billed per command, remote): lobby tick and answer-count interval poll Redis even when nothing changes (~120 commands per lobby, ~80 per question); `deleteGame` does one sequential `GET` per player; Redis URL credentials not percent-decoded. | Quota / bill grow with wall-clock time; slow cleanup for big games. | Review T-008 + user context | T-022 (P1). |
| D-010 | Local DB schema was built with `prisma db push --accept-data-loss`; `prisma/migrations/` is gitignored. | No reproducible schema history; `migrate dev` will detect drift and propose a reset; no safe path to any future deployment. | Retro review T-007 | Baseline a first migration once T-008's schema change is applied, stop ignoring `prisma/migrations/` (config change, user decision). |
